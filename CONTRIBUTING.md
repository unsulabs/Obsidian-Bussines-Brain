# Contribuir

Usa Python 3.11 o posterior y las dependencias de `requirements.txt`. Describe el problema, el cambio y cómo se verificó. Para cambios de runtime ejecuta `python -m unittest discover -s tests -v`; añade una prueba de comportamiento cuando corresponda. Para skills comprueba rutas, instrucciones y alcance, además de la sintaxis.

Trabaja con fixtures sintéticos y rutas temporales. Nunca adjuntes datos de negocios, conversaciones, credenciales ni capturas de una instancia real a issues o pull requests. Si necesitas reproducir un problema, crea un caso mínimo inventado desde cero.

Preserva las decisiones y datos de cada instancia: no introduzcas país, moneda, impuesto, forma societaria u organigrama por defecto. Mantén la procedencia de recursos de terceros y añade sólo material que puedas distribuir. Las contribuciones propias se ofrecen bajo la licencia MIT del repositorio.

Un cambio no debe afirmar aceptación empresarial por pasar pruebas estructurales. Documenta los límites que afectan al uso.

Mantén los cambios de producto en este repositorio público y las instancias, su configuración y sus datos fuera de Git. Para trasladar una mejora desde otro entorno, extrae un cambio mínimo y revisa su contenido e historial. Nunca fusiones ciegamente ramas privadas ni incorpores respaldos como actualizaciones del producto.
